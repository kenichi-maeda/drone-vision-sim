# Drone vision handoff — 2026-11-10

## Verified result

The bounded visual-search-and-approach run succeeded. Birdie took off, entered
OFFBOARD, acquired a camera-only YOLO detection, centered it, and advanced about
0.72 m. The YOLO box grew to the configured 2.0x visual-size goal, after which
the controller requested AUTO.LAND. PX4 reported disarm by landing; MAVROS
confirmed `armed: false` and `landed_state: 1`.

The approached object was the yellow duckie prop. COCO YOLO labeled it class 32
(`sports ball`); it did not label it as a bird. The run used image-derived YOLO
detections and standard MAVROS vehicle state. It did not read Matrix target
poses, labels, or simulator object positions.

The vehicle spawn and target asset orientations remain at their previously
approved values. Only one Matrix engine was running. At handoff, Matrix, Birdie,
PX4, MAVROS, camera, and the workbench containers were up; the drone was landed
and disarmed. The workbench controller is one-shot and remains in its completed
state until the workbench is restarted.

## Changes in this run

- YOLO can select a configured COCO class or use `target_class_id=-1` to report
  the highest-confidence COCO detection.
- Target confirmation requires repeated detections from the same class. After
  lock, the controller can maintain the target through a class-label change
  when the YOLO box remains continuous in image position and size.
- Search acquisition filters detections at the edge of the vertical image,
  where this yaw/forward-only controller cannot steer vertically.
- Fixed an approach crash caused by unpacking the newly extended detection
  tuple as if it still had four fields.
- The launcher defaults to any COCO class at confidence 0.35. Set
  `YOLO_TARGET_CLASS_ID` to a COCO class ID when a test needs a specific class.

## Current limits and next steps

- The COCO model misclassified the duckie as `sports ball`; this run verifies
  image-based approach to a YOLO-detected object, not semantic accuracy for
  every object class.
- Add target selection per experiment and validate it against the desired
  object using camera frames only. Do not use simulator object labels or poses
  to steer.
- Keep the automatic landing and disarm checks. After landing, restart the
  workbench before another mission; do not start a second Matrix engine.
- The Matrix engine uses the persistent local `ente-arm64v8-old-gate` image
  (tagged to the canonical distro name) with the verified DTPS physics-gate
  startup fix. The newer cached Matrix image previously needed broader bridge
  patches and had less stable sensor/pose behavior in these trials.
